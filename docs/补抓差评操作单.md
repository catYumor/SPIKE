## 1. 抓差评

**前提**：`crawler/.secrets/cookies.txt` 里的 cookie 还有效（京东登录态一般能撑几天）。
失效了就重新导出一次，方法见 `crawler/.secrets/README.txt`。

```bash
cd /mnt/d/workspace/SPIKE
source scripts/spike-env.sh

# 差评：每个商品 200 条，12 秒/条（≈120 秒/页）
python crawler/jd_slow_crawl.py --score 1 --target 200 --review-interval 12
```

**建议后台跑**，不然终端一直占着：

```bash
bash scripts/start_slow_crawl.sh 0 3600 12
```

看进度：

```bash
python crawler/jd_slow_crawl.py --status
```

> ⚠️ 注意：`--status` 统计的是文件里全部 jd 数据（含已有 500 条好评），
> 所以会显示 `500/500`。**新抓了多少要看日志**：
> `tail -f logs/crawl.log`，找「本次新增 N 条」。

抓完再补中评（可选，能提升情感分布质量）：

```bash
python crawler/jd_slow_crawl.py --score 2 --target 100 --review-interval 12
```

结果会**自动追加**到 `data/raw/<sku>.jsonl`，按 `review_id` 去重，
星级不同的进度文件分开存，互不覆盖。**这一步不需要手动合并。**

## 4. 怎么判断成功了

打开 <http://127.0.0.1:5000>，重点看两个数：

| 位置 | 昨天（只有好评） | 目标 |
|---|---|---|
| 健康总览 → 整体负面率 | 3.0% | **明显上升（10%+）** |
| 健康总览 → 痛点 / 优势 | **0 / 7** | **痛点 ≥ 1** |
| 优势与痛点页标题 | 「相对短板」（橙色提示条） | 变回「痛点」，提示条消失 |
| 竞品差距 → 最大短板 | 客服服务 −13.1pp | 数值会明显变化 |

只要「痛点」不再是 0，就说明数据补对了——
页面上那条橙色「未达阈值」提示会自动消失，因为不再走降级逻辑。

## 5. 可能遇到的问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 一直「🚫 被限流」 | 京东 WAF 封了 IP/账号 | 等 1–2 小时再试；或换网络（手机热点） |
| `没有 cookie` | cookie 文件缺失或格式不对 | 重新导出，见 `crawler/.secrets/README.txt` |
| 抓到的还是全是 5 星 | `--score` 没生效 | 确认命令行里有 `--score 1` |
| `refresh_all.sh` 第 2 步失败 | 数据里有脏行 | 单独跑 `python crawler/validate_jsonl.py data/raw/*.jsonl` 看哪行 |
| HDFS 起不来 | safemode 没退出 | `bash scripts/spike-hdfs-status.sh`；再不行 `bash scripts/spike-hdfs-start.sh` |
